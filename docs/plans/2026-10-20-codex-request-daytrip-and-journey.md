### 2. 日送り中に「隊の様子」を見せる

**狙い**: 派遣した隊が旅している所を見たい。帰還報告が「結末」、日々の様子が「中継」になり、呼び戻し(`recall`)が盲目でなく、見てから決める操作になる。

**データはもう全部あります。** 新しくシミュレートしないでください。

- 位置: `Expedition.steps`(日付→位置の表)。`src/ui/app.ts` の `stepToday(e)` と `positionText(st)` が「往路: 拠点の街–山村の道中」の文を作る。ワールドタブはこれで隊のマーカーを置いている
- 出来事: `Expedition.result.log: LogEntry[]`(`{ day, kind, text }`)。**`day` は遠征の何日目か(1始まり)** で、`src/core/game.ts` の `combineLegs` が往路の行はそのまま、現地の行を往路の日数ぶん、復路の行を往路+滞在ぶんずらして結合している。暦の日は **`e.startDay + l.day - 1`**
- `planSteps`(`src/core/world.ts`)の都合で、道0日の行き先は出発した日がそのまま現地1日目になる。つまり森の日帰りは出発日に現地の出来事が起き、翌日に帰還する

**開示の規則: 「昨日まで」。** 暦の日が `state.day` より前の行だけ見せる。出発した日の出来事をその日のうちに見せないのは、「報告は翌朝に届く」を帰還報告と揃えるため(日帰りでは中継は空のまま帰還報告が届く。それでよい)。

実装:

1. `src/core/journey.ts`(新規、DOM 非依存)に
   ```ts
   /** 日送り中に読める道中。暦の日 today より前の行を日ごとにまとめる(古い日が先)。行の無い日も入れる */
   export function journeyUntil(e: Expedition, today: number): { day: number; lines: LogEntry[] }[]
   ```
   を書く。対象の日は `e.startDay` から `min(today - 1, e.returnDay)` まで(道の日で何も起きなかった日は `lines: []`)。`today <= e.startDay` なら空配列。
2. ホーム(`src/ui/home.ts`)に `journeyBlock()` を足し、`noticesBlock()` の直後・名簿の前に置く。見出しは **「隊の様子(昨日)」**。派遣中の隊が無ければブロックごと出さない。隊ごとに:
   - 1行目: `隊長 ○○の隊: ` + `positionText(stepToday(e))` + ` / N日目に帰還予定`
   - 続けて `journeyUntil(e, state.day)` の最後の日(= 昨日)の行を、ログタブと同じ `log-<kind>` のクラスで並べる。行が無ければ `昨日は道中に変わったことはなかった。`。昨日が出発日より前(= 今日出発した隊)なら `今朝出発した。最初の便りは明日の朝に届く。`
3. 派遣タブの `awayRow`(`src/ui/dispatchTab.ts`)に「これまでの道中」を足す。`journeyUntil` の全日を古い順に、日ごとに `N日目` の見出しを付けて並べる。長くなるので `<details>` で畳み、見出しは `これまでの道中(N日分)`。呼び戻すボタンはそのまま。
4. 呼び戻し(`src/core/game.ts` の `recall`)は `combineLegs(legs.out, null, legs.back, legs.items, walked)` で結果を組み直し、現地の行を全部捨てる。これだと **開示済みの現地の行が呼び戻しで消える**ので、組み直す前に開示済みの現地の行を取っておき、呼び戻しの行の直前に戻す:
   ```ts
   const outDays = pathDays(legs.outNodes, s.world);
   // 今日までに現地で起きた行(往路の行は day <= outDays、復路の行は day > outDays + 滞在 なので日で切り分けられる)
   const seen = e.result.log.filter((l) => l.day > outDays && l.day <= walked);
   const r = combineLegs(legs.out, null, legs.back, legs.items, walked);
   const at = r.log.findIndex((l) => l.day > walked);
   r.log.splice(at < 0 ? r.log.length : at, 0, ...seen, { day: walked, kind: 'event', text: 'ギルドからの呼び戻しを受け、引き返した。' });
   ```
   往路の途中で呼び戻したときは `seen` が空で今と同じ結果になる(往路の行を日で切り分けない簡略はそのまま)。持ち帰りの数値(素材・経験・負傷)は今までどおり現地の分を捨てる(確認ダイアログで「現地の成果は持ち帰れません」と言っているので、行だけ残っても矛盾しない)。
   `recall` の冒頭のコメント「結果を明かさないよう、受け付けるだけにする」は、中継で翌朝に分かるようになるので「道中で全滅した隊は表が引き返しになっている。中継で翌朝に分かるので、ここでは受け付けるだけにする」に直す。
5. `docs/DESIGN.md`:
   - 0 章の表「時間」の行: `派遣は出発時に全行程を確定し、帰還日に開示` → `派遣は出発時に全行程を確定。道中の出来事は翌朝から日ごとに読め、結末(持ち帰り・成長)は帰還日に開示`
   - 2 章の「派遣中の隊はワールド上に現在位置を表示。呼び戻し(帰還方向への切替)だけ可能」に「ホームに昨日までの道中(出発時に確定した結果の開示。乱数は引き直さない)」を足す

`GameState` に項目は足さない(`result.log` は既にセーブに入っている)。版番号も上げない。

テスト(`tests/journey.test.ts`、`tests/helpers.ts` の作り方に倣う):

- 森の洞窟へ現地1日: 出発日の `journeyUntil(e, s.day)` は空。`advanceDay` 1回で `s.history` に入り `s.expeditions` は空(日帰りの確認)
- 古い坑道へ現地2日(拠点→山村→坑道で片道2日。噂のままなら `survey` で出す): 出発翌日は往路1日目の分だけ、翌々日は往路2日分、その翌日は往路+現地1日目。各日の `lines` が `e.result.log` を `e.startDay + l.day - 1` で切った物と一致する。今日の行(暦の日 `=== today`)は含まない
- 道中で全滅した隊(`result.wiped` かつ往路で倒れた seed を探す。`tests/world.test.ts` の `simulateTravel` の例が参考になる)は、全滅の翌朝の中継にその行が出る。これは仕様(ワールドの位置が引き返すので今も半分見えている)
- 行の無い日は `lines: []` で入る(道で何も起きなかった日。seed を変えて見つけるか、`result.log` を直接組んだ `Expedition` を作って確かめる)
- `recall` の後も、呼び戻した日までの行がそのまま残り、そのあとに「ギルドからの呼び戻しを受け、引き返した。」と復路の行が続く
- `game.test.ts` / `world.test.ts` の既存の呼び戻しのテストが緑のまま

ブラウザ: `npm run build` のあと `npm run test:browser`。幅 375px でホームの「隊の様子」と派遣タブの「これまでの道中」が横にはみ出さないこと、コンソールエラー 0 を確認し、`docs/VERIFICATION.md` に日付付きで記録する(seed・確認した画面・スクリーンショットの置き場 `artifacts/screens/`)。

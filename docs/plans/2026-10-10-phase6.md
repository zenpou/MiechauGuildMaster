## 決定事項(本体の設計判断。変えない)

### 複数フロア(移動費モデル)
- 階の探索は **別々の派遣**。`DispatchOrder.target.floor` に `f2` を指定すると、前の階の `stairs_down` を踏んだ記録(`visited`)がある時だけ出せる(`f3` は `f2` の階段が要る)
- `f2` の派遣は、隊が前の階を通り抜ける **移動費(transit)** を払う: 前の階で「入口 → stairs_down」の既知の最短経路の歩数(各1歩)。往路で1回、復路で1回。探索は `f2` の入口(階段の隣の `entrance` マス)から始まる
- 実装: `ExploreInput.transit`。初日の歩数予算から `transit` を引く(足りなければ翌日以降に繰り越す)。`homeDist` に常に `transit` を足す(帰路の予約)。往復できない日数なら既存の「出直す」が働く
- 鍵と扉: `door` マスは `CellDef.key` のアイテムを持っているときだけ通れる。持ち物は出発時の在庫で決まる(`ExploreInput.keys`)。鍵(`kind: 'key'`)は消費しない。鍵は **`item` を持つ `treasure` マス** で1個手に入る(金も罠も無し。持っていれば何も起きない)。手に入れた鍵は `result.items` に入り、帰還で在庫へ(在庫は最大1個)

### タスクV1: 探索(複数フロア・鍵・扉)
**所有**: `src/core/explore.ts`、`src/core/dungeon.ts`(追加のみ)、`tests/explore.test.ts`、`tests/dungeon.test.ts`(鍵の到達性のテストのみ)
- `ExploreInput` に `transit?: number` / `keys?: string[]` / `hiddenBonus?: number` を足す(省略時 0 / [] / 0。**既存の乱数の引き方・結果は変えない**: `npm run sim -- 20 30` が一致すること)
- `floorTransit(dungeon, floorId, progress): number | null`(export): `f1` は 0。`fN` は `fN-1` の `stairs_down` が visited にあれば、前の階の入口からそのマスまでの既知の最短経路の歩数(+それ以前の階の transit)。階段が未踏・経路が無ければ null
- `homeDist` に `transit` を足す。初日の予算から `transit` を払う(予算を超える分は翌日へ)。ログ「前の階を抜けて N 歩」
- `door` は `keys` を持つときだけ通れる(`know.keys` に `keys` を渡す)。`cellDepths` は鍵を全部持った形でも測る(扉の奥の深度を −1 にしない)
- `treasure` マスに `item` があるとき: 金と罠の判定をせず、`keys` に無ければ `result.items[item] = 1`、ログ「○○を手に入れた」。持っていれば「もう持っている」
- `stairs_down` マスに入ったらログ「下り階段を見つけた」(trace のイベント kind `stairs`)
- `hiddenBonus` は隠し通路の発見率に加算(上限0.95)
- テスト: transit 分だけ予算が減る・帰路を予約する、transit で往復できない日数は「出直す」、扉は鍵が無いと通れず有ると通れる(`keys`)、鍵の宝箱は金も罠も無く1個、持っていれば取らない、`floorTransit`(階段が未踏なら null)、`cellDepths` に -1 が残らない、hiddenBonus で発見が増える(統計・固定seed)

## 計測(タスクX)
`scripts/dragon.ts`: `npm run sim:dragon -- [seeds=10] [days=200]`。bot が毎日: メール返信 → 施設を優先順に建てる → 装備を作って着ける → 条件を満たす者を転職 → 隊(最大2〜3隊)を「今の力で行けるいちばん奥のダンジョン」へ(探索→ボス)→ 依頼をこなして資金を稼ぐ。出力: 竜討伐までの日数の分布(最小/中央/最大)、討伐できなかった seed の停滞理由(どの段で止まったか)、各ダンジョンの初踏破日。目標: 60〜90日で討伐できる seed が出ること。外れたら敵・装備・経済の係数を計測で動かす

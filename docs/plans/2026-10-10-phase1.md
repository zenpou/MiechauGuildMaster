### 生成 `generateAdventurer(rng, { id, quality?, level?, usedNames? })`

- 8能力の釣鐘分布は前作と同じ値域
- **適性の形**(第6節): 50% 尖り / 35% 二山 / 15% 平ら
  - 尖り: 1役を 62〜98、他は `bell(10, 62)`
  - 二山: 五角形で**隣り合う**2役(fighter-warrior-priest-gatherer-scout-fighter の順)を 55〜85、他は `bell(10, 50)`
  - 平ら: 全役 `bell(40, 65)`
  - quality は前作同様に少し上乗せ。全部 0〜100 に丸める
- 初期の職: 二山・平らは下級5職から等確率、尖りは 60% でその役の下級職、40% で別の下級職(転職で化ける)
- 性格は6種から等確率、特性は前作と同じ確率(55%で1、11%で2、隠れ確率あり)
- `persona`: `persona.json` の各リストから1語ずつ。`likes` と `dislikes` は別の語
- `loyalty`: `int(40, 60)`。`status: 'idle'`、`assignment: null`、`equipment` 全部 null、`skills: []`
- `history`: `{ hiredDay: 0, expeditions: 0, kills: 0, visits: {}, raisesRefused: 0, warnedDay: null }`
- `salary = salaryOf(a)`

### データ

- `traits.json`: 前作の11種をそのまま(`GuildQuest/src/data/traits.json`)
- `names.json`: 前作の40名をそのまま+20名足して60名
- `persona.json`: hobby / talent / likes / dislikes 各15語以上(日本語、短い名詞)
- `policies.json`: 前作の6種をそのまま(`GuildQuest/src/data/policies.json`)

### テスト(What)

- 同seedで同じ冒険者が生まれる
- 適性の形が3種類とも出て、比率がおよそ 50/35/15(seed 500人で ±8%)
- 二山は隣り合う2役にだけ高い
- `jobAptitude` は上級職で2役の平均
- `effectiveStats` の戦闘系は適性で、非戦闘系は適性に影響されない
- 疲労40以下は能力そのまま、100で約0.6倍
- `addExp` でレベルが上がり、日給は変わらない
- `carryCapacity` はギャザラー役で1.5倍
- 日給は最低8G

## タスクC: ダンジョンのグリッドと探索率(`src/core/dungeon.ts`)

**所有ファイル**: `src/core/dungeon.ts`, `src/data/dungeons.json`, `src/data/items.json`, `tests/dungeon.test.ts`

### グリッド

`FloorDef`(types.ts)は `rows: string[]`(1文字=1マス)+ `legend: Record<char, CellDef>`。これを解析する。

```ts
export interface Grid {
  width: number; height: number;
  cells: CellDef[];          // index = y * width + x
  entrance: number;          // kind 'entrance' のindex
}
export function parseFloor(def: FloorDef): Grid;
export const idx = (grid: Grid, x: number, y: number) => y * grid.width + x;
export const xy = (grid: Grid, i: number) => ({ x: i % grid.width, y: Math.floor(i / grid.width) });
/** 通れるマス(wall 以外)。door は keys に鍵があるとき、hidden は hiddenFound に入っているときだけ通れる */
export function isPassable(grid: Grid, i: number, know: { keys: string[]; hiddenFound: number[] }): boolean;
/** 上下左右の通れる隣接マス */
export function neighbors(grid: Grid, i: number, know): number[];
/** known(既知=踏んだ or 見た)のマスだけを通る最短経路(BFS)。from と to を含む index 列。無ければ null */
export function shortestPath(grid: Grid, from: number, to: number, known: Set<number>, know): number[] | null;
/** 探索率 0〜1 = visited ∩ 通行可能 / 通行可能マス総数(hidden も含む、wall は除く) */
export function exploredRate(grid: Grid, visited: number[]): number;
/** 立っているマスから「見える」マス = 上下左右の隣接(壁も含めて見える) */
export function visibleFrom(grid: Grid, i: number): number[];
/** 既知だが未踏のマスのうち、通れるもの(フロンティア) */
export function frontier(grid: Grid, visited: Set<number>, seen: Set<number>, know): number[];
/** visited に無い hidden マスは「壁に見える」。この判定を1か所に */
export function looksLikeWall(grid: Grid, i: number, hiddenFound: number[]): boolean;
```

legend の文字は自由だが、`#`=wall、`.`=floor、`E`=entrance を推奨。

### 最初のダンジョン `forest_cave`(`dungeons.json`)

- `node: "forest_cave"`(ワールドはフェーズ4。今は名前だけ)
- フロア `f1` を1枚、**12×12**。入口は左端中央あたり。構造: 入口から3方向に分かれる通路、部屋4つ、行き止まり2本、**奥へ行くほど巣と採取点が濃い**
- マスの内訳: entrance 1 / gather 4(herb×2, moss_ore×1, slime_gel×1。`item` に素材ID)/ nest 2(`enemy: goblin` と `enemy: wolf`)/ symbol 1(`enemy: goblin_chief`、最奥)/ treasure 2 / trap 2(`trap: "spike"`)/ hidden 3(短い隠し通路で近道になる配置)/ 残りは floor と wall
- 通行可能マスは **60〜75** 個(1日12歩前後で、4〜5日通って埋まる規模)
- `enemies`: goblin 重み5 group [1,3] / wolf 重み3 group [1,2] / slime 重み3 group [1,2]
- `recommended: 180`、`rescueCost: 120`
- `desc` は1〜2文

## タスクD: 探索シミュレーション(`src/core/explore.ts`)— 第2波(A〜Cの完了後)

**所有ファイル**: `src/core/explore.ts`, `tests/explore.test.ts`

前作 `GuildQuest/src/core/expedition.ts` の「出発時に全行程を決定論的に確定する」「撤退しきい値=方針+隊長の性格×0.6+疲労」「帰還時の負傷・経験値・特性判明・関係値」の考え方を使い、**1日3ステップのイベント抽選をマス移動に置き換える**。

### 入出力

```ts
export interface ExploreInput {
  rng: Rng;
  dungeon: DungeonDef;
  floorId: string;                       // フェーズ1は 'f1'
  members: Adventurer[]; leaderId: string; policy: string;
  progress: DungeonProgress;             // 出発前の知識(visited / hiddenFound)。変更しない
  days: number;                          // 現地日数
  items: Record<string, number>;         // 持ち物(potion など)
  relations: Record<string, number>;
  startDay: number;
}
export function simulateExploration(inp: ExploreInput): ExpeditionResult;   // types.ts の型
```

`ExpeditionResult.mapDeltas` に今回新しく踏んだマスと見つけた隠し通路を入れる。`progress` 自体は書き換えない(game.ts が帰還日にマージする)。

### 知識の表現

- `visited`: progress の visited(既踏)。今回踏んだ分は別の Set に積み、両方の和を「既知の踏んだマス」として使う
- `seen`: visited の各マスから `visibleFrom` で導出(永続化しない)
- `hiddenFound`: progress + 今回見つけた分
- `known = visited ∪ seen`。`frontier` = seen かつ 未踏 かつ 通れそう(`looksLikeWall` でない)

### 1日の進め方

1. 歩数予算 `budget = round(12 × 隊長の explore.speed)`。初日は入口から、2日目以降は前日の野営位置から
2. 目標マスを選ぶ(下記)。既知マスだけを通る `shortestPath` で経路を引く。目標がフロンティアなら最後の1マスは未知
3. 1歩進むごとに歩数を消費: **既踏マスへは1、未踏マスへは2**。予算が尽きたらその場で止まる
4. 分かれ道(通れる隣接が3以上)で新しい目標を選ぶとき、`rng.chance(explore.hesitate)` なら1歩失う。`forkRandom` なら候補の上位3つから乱択
5. マスに入ったときのイベント(下記)。イベント後に撤退判定と休憩判定
6. **最終日**: 1歩ごとに「残り歩数 ≥ 入口までの既知最短経路の歩数+次の1歩の費用」を確認し、満たさなくなったら帰路に入る。帰路は既知の道なので1歩=1
7. 最終日でない日の終わり: その場で野営。全員 疲労−8、HP+20%(maxHP比)。ログに「野営」
8. 1日の疲労: 全員 +10(特性 fatigueRate 倍)、戦闘ごとに +4

### 目標の選び方(隊長の性格)

```
候補 = frontier
   + 寄り道対象(detour='nest' → 既知の未消化の nest/symbol マス、detour='treasure' → 既知の未消化の treasure/gather マス)
各候補 f について:
   dist  = 現在地からの経路長(既知経由、未踏の最後の1歩は2)
   depth = 入口からの経路長(全マスの中で正規化 0〜1)
   score = venture × depth − thorough × (dist / 最大dist) + 寄り道なら +0.5 + rng.range(0, 0.05)
最大の score を選ぶ(forkRandom なら上位3から乱択)
detour='avoid' の隊長は nest/symbol マスを経路から外す(他に道が無いときだけ通る)
detour='injured' の隊長は、誰かのHPが 50% 未満になったら以後その日は入口へ向かう
候補が無い(全部踏んだ)なら入口へ戻って終了(log「地図は埋まった」)
```

### マスのイベント(1回の派遣で各マス1度)

| kind | 処理 |
|---|---|
| gather | 採取。成功率 = clamp(0.35 + 隊の最大 gather / 40 + 運×0.1, 0.1, 0.95)。量 1〜2、`pack` スキル持ちがいれば +1。積載(Σ carryCapacity)を超える分は置いていく(log) |
| treasure | 30〜80G。30%で罠付き(下の trap と同じ判定) |
| trap | 回避: 隊に `first_strike` 持ちがいれば trapDisarm の確率で解除。そうでなければ 器用さ最大の者で `rng.chance(clamp(0.4 + dex/40 + Σ trapCare, 0.1, 0.95))`。失敗で乱択1人に maxHP の 10〜20% ダメージ、全員 疲労+5 |
| nest | `enemy` の群れ(ダンジョンの enemies 表の group、無ければ 2〜3)と戦闘 |
| symbol | `enemy` 1体と戦闘(撤退可) |
| hidden | 踏み込もうとしたとき(目標が隣接の hidden のとき)、`rng.chance(clamp(0.2 + 隊の最大 scout / 50, 0.1, 0.9))` で発見。発見したら hiddenFound に入れて通れる。失敗なら壁扱いのまま(その日は再挑戦しない) |
| floor | `rng.chance(dungeon.encounterRate ?? 0.04)` で遭遇。敵は enemies 表から weighted |
| entrance / stairs | 何もしない(階段はフェーズ6) |

戦闘は `combat.ts` の `runCombat`。味方ユニットは `makeAllyUnit(a, effectiveStats(a))`。`fleeBelow = retreatThreshold × 0.55`。勝てば敵の loot を素材に(積載内)、全員 down なら全滅。戦闘後 down の者は HP20% で復帰(前作と同じ)

### 撤退・休憩・全滅

- 撤退しきい値 = `clamp(policy.retreat + 隊長の retreatBias × 0.6 + (平均疲労 > 70 ? 0.08 : 0), 0.1, 0.75)`。イベント後に隊の平均HP比がこれ未満なら入口へ向かい、着いたら終了(`retreated: true`)
- 休憩: `restMode='average'` なら平均HP比、`'any'` なら最低HP比が `restHp` 未満のとき。3歩消費、全員 HP+15%(ヒーラー役がいれば +heal の ratio 分追加)。1日2回まで
- 全滅(`wiped`): 全員 負傷 2〜4日、`lostMaterials` に素材を全部移し materials は空、`rescueCost = dungeon.rescueCost`。入口に戻ったことにして終了

### 帰還時の集計

- `injuries`: 終了時HP比 < 0.3 の者は 1〜3日、戦闘で down した者は 2〜4日(大きい方)。全滅は上記
- `expGain`: (新しく踏んだマス数 × 2 + 日数 × 5 + Σ 撃破exp / 人数) × policy.expMult × 特性 expRate
- `fatigue`: 上記の累計(member ごと)
- `relationDeltas`: 戦闘のかばう・回復(`CombatCtx.rel`)+ 共に帰還 +1(全組)
- `revealedTraits`: 未判明の特性を 各派遣 25% で1つ判明
- `kills`, `itemsUsed`(potion), `materials`, `gold`
- `repGain: 0`(評判はフェーズ4の依頼で)
- `success`: 撤退も全滅もしていなければ true
- `questProgress: {}`、`returnDialogue: []`(フェーズ5)
- `log`: 日の始まり「N日目」、移動のまとめ(「北へ進み、新しく5マス踏んだ」程度)、イベント、戦闘、野営、終了理由。種別 `map` で地図更新の行

### テスト(What)

- 同入力で同じ結果(決定論)
- 1日で踏めるマス数は歩数予算に収まる(速度係数の影響を含む)
- **未踏マスへの移動は2歩、既踏は1歩**: 同じ経路を知識あり/なしで走らせ、知識ありの方が奥へ届く
- 最終日は入口に戻って終わる(全滅・撤退以外)
- 慎重の隊長は入口近くから埋める(訪問マスの平均深度が勇敢より浅い)
- 勇敢は巣に寄り道する(nest の戦闘が起きる確率が高い)
- 臆病は nest を避ける(他の道があれば nest を踏まない)
- 全滅すると素材を失い救助費用が付く
- 隠し通路は hiddenFound に入ると通れ、mapDeltas.hidden に載る
- 積載を超えた素材は持ち帰れない
- `progress` 引数は書き換えられていない

# フェーズ4 実装プラン: ワールドと依頼

> 2026-10-10。ROADMAP フェーズ4。設計の正本は [DESIGN.md](../DESIGN.md) 第2節(ワールドマップ)・第7節(依頼とワールド)・第6節(募集・契約金)。
> 規約と共有IDは [phase1](2026-10-10-phase1.md)〜[phase3](2026-10-10-phase3.md) を引き継ぐ。
> 「確認したいこと」: 締め切りだけで進行の圧力が十分か(日給と依頼の締め切りで、何もしない日が損になるか)。

## 決定事項(本体の設計判断。変えない)

| 項目 | 決定 |
|---|---|
| ワールドの形 | ノードと道。拠点の街 `base` を中心に、鍛冶の街 `forge_town`(東)、学院の街 `academy_town`(北)、山村 `mountain_village`(西)。ダンジョンは 森の洞窟(拠点の南、0日=隣接)、古い坑道(山村の先、拠点から2日)、**廃れた塔 `ruined_tower`**(鍛冶の街の先、3つ目のダンジョン、拠点から3日)。中継地 `camp_north`(拠点と学院の街の間の野営地) |
| 道 | `days`(片道日数)と `danger`(0〜1、真の危険度)。隊が通ると `world.measuredDanger` に実測値として開く。隠し道は1本(山村→古い坑道の近道、`hidden: true`、山村を3回訪れると開く)。地理(ノードと道の存在・日数)は最初から全部見える |
| 移動の扱い | 派遣の `returnDay = 出発日 + 往路日数 + 現地日数(daysSpent) + 復路日数`。`Expedition.steps` に日付ごとの位置(ノード/道、outbound/stay/return)を入れ、ワールド画面で現在位置を見せる。移動日数は派遣画面に「往復N日+現地M日」と表示 |
| 道中の戦闘 | 移動1日ごとに `rng.chance(danger × (1 − 隊の斥候役の有無×0.3))` で遭遇1回。敵は道ごとの `enemies` 表(無ければ隣接ダンジョンの表)。戦闘は `combat.ts`、結果はログに「道中」として載る。全滅したら現地に行かず帰還(負傷・救助費用は道の `rescueCost`=50×日数) |
| 呼び戻し | 派遣中の隊に `recall` を出すと、その日の位置から帰還方向に切り替わる(現地なら即帰路、往路なら引き返す)。結果は出発時に確定しているので、呼び戻し後の道中は「復路の残り日数分の遭遇」だけ再計算せず、**出発時に全日程分の遭遇を先に引いておき**、呼び戻しは使う分を途中で切る |
| 依頼の種類(フェーズ4) | 納品 `deliver` / 討伐 `hunt` / 探索 `explore` / 護衛 `escort` / 運搬 `transport` / 解放依頼 `unlock`。踏査依頼は第2部 |
| 依頼の発生 | 街ごとに毎日 `boardChance`(拠点0.5、街0.4、村0.3)で1件、掲示板上限(拠点4・街3・村2)。テンプレート(`quest-templates.json`)から街の `questWeights` で種別を選び、パラメータは seed+日付で決定論的に。難度は評判Lvで段階解放(`minRep`) |
| 依頼の可視 | 拠点の依頼は常に見える。他の街の依頼は `world.visitedNodes` に入ってから。訪れる=隊がそのノードを通過・滞在する |
| 受注 | 拠点で受ける(街へ行く必要はない)。同時受注は3件(受付施設はフェーズ6)。受注期限 `acceptBy`、納期 `dueDay`、護衛は `departDay` 固定 |
| 達成の判定 | 納品: 拠点の在庫から納める(ボタン)。討伐: 受注後の帰還で `result.kills[enemy]` を累計。探索: 指定ダンジョンの探索率が `percent` 以上になった帰還時。護衛: 出発日に `escort` 行動で `from→to` の経路を出し、全滅せずに `to` に着いたら達成。運搬: `transport` 行動、荷物の重さ `cargo` を積載に含め、`to` に着いたら達成 |
| 報酬 | 資金+評判。納品は素材の売値の 2.5倍相当、討伐は敵expの×15、探索は 150〜400、護衛は 道の日数×80×(1+danger)、運搬は 日数×60 |
| 期限切れ | 受注前に `acceptBy` を過ぎたら消える(評判は変わらない)。受注後に `dueDay` を過ぎたら失敗で評判−1、お知らせ |
| 解放依頼(フェーズ4は1本) | 鍛冶の街の職人「鉄鉱石を5個納めてくれ」→ 達成で `iron_sword` / `iron_armor` のレシピ解放(`unlockedBy`)。それまでこの2つは作れない |
| 評判 | 0〜。5段階のしきい値 0 / 8 / 20 / 35 / 55(前作)。効くもの: 候補者の数と質、依頼の `minRep`、街の情報 |
| 勘違いイベント | 前作の仕組み(行動タグ→日送り時に抽選→噂→評判+2〜5→主人公の本音)を `scenes.ts` として移植。台詞は**仮**(`misunderstandings.json` に5件、「(仮)」付き)。タグはフェーズ4で出せる範囲: `hire_talent` / `job_change_big`(転職はフェーズ6なので保留)/ `dispatch_safe_weak` / `return_first_success` / `return_underdog` / `facility_built` / `rep_milestone` / `day_idle` |
| 募集 | 毎日 候補者 1 +(評判Lv3以上で+1)+(40%で+1)人到着、最大8人保持、5日で入れ替わり。質は評判Lvで上がる(quality = (Lv−1)×0.2)。契約金 = 日給×4。雇用上限 = 6 + 宿舎の capacity。解雇は待機中のみ、費用なし。前作の仕組みそのまま |
| 経済の圧力 | 日給+維持費は今のまま。依頼報酬が主な収入。初期支援金は維持。`playstyles.ts` で「依頼を受けない」「受けるが締め切りを無視」「締め切り優先」の3通りを60日比べ、締め切りの圧力を測る |
| 3つ目のダンジョン | 廃れた塔 `ruined_tower`: 16×16、2フロア(f1/f2、階段あり。複数フロアの探索はフェーズ6だが、地図は先に作る。フェーズ4では f1 だけ探索可)。敵: `ghoul` グール / `gargoyle` ガーゴイル / `wisp` 鬼火(fire)/ シンボル `tower_keeper` 塔の番人。素材: `ancient_cloth` 古布 / `crystal` 水晶 / `wisp_ember` 鬼火の残り火 |

## タスクN: ワールド(第1波)

**所有ファイル**: `src/core/world.ts`(新規)、`src/data/world.json`(新規)、`src/data/dungeons.json`(廃れた塔の追加)、`src/data/enemies.json`、`src/data/items.json`(塔の素材)、`src/core/explore.ts`(道中の戦闘を `fightOnRoad` として export する小さな追加のみ)、`tests/world.test.ts`、`tests/dungeon.test.ts`(塔の到達性)

- `world.json`: `{ nodes: WorldNodeDef[], edges: WorldEdgeDef[] }`。`WorldEdgeDef` に `enemies?`、`rescueCostPerDay?` を足したい場合は world.ts 内の型で拡張し報告
- `world.ts`: `travelDays(from, to, knowledge)`(既知の道だけ、hidden は found のときだけ。最短日数。Dijkstra)、`route(from, to, knowledge): string[]`(ノード列)、`planSteps(route, stayDays, startDay): WorldStep[]`、`visibleQuestsTowns(s)`、`simulateTravel(rng, members, route, direction)`(道中の遭遇をまとめて引く。結果はログと負傷・kills)
- 廃れた塔の地図(16×16×2フロア。f2 の階段は f1 の最奥。フェーズ4では f1 だけ使う)
- テスト: 最短日数、hidden の有無で経路が変わる、steps の日付が連続、道中の遭遇が danger に比例(1000回の統計、固定seed)、塔の到達性

- テスト: 生成の決定論、掲示板の上限、minRep の解放、受注期限切れで消える、納期切れで失敗と評判−1、納品で在庫が減り報酬が入る、討伐の累計、探索率の達成、解放依頼で `unlockedBy` のレシピが開く、評判Lvの境、勘違いの抽選が決定論

## タスクP: 募集と game.ts の統合(第2波、N・Oの後)

**所有ファイル**: `src/core/game.ts`、`src/core/recruit.ts`(新規)、`src/core/craft.ts`(`unlockedBy` の反映)、`tests/game.test.ts`、`tests/recruit.test.ts`

- `recruit.ts`: 候補者の到着・入れ替わり・雇用(契約金、上限)・解雇

- `newGame`: `world.visitedNodes = ['base', 'forest_cave']`、拠点の初期依頼2件

## タスクQ: UI(第3波)

**所有ファイル**: `src/ui/**`

- ワールドタブ(新設): ノードと道を SVG で描く(座標は world.json)。訪問済み/未訪問、噂のダンジョン、道の日数と危険度(実測なら値、未測なら「?」)、派遣中の隊の現在位置。ノードを選ぶと依頼掲示板(訪問済みなら)
- 依頼タブ(新設): 受注中(残り日数、進捗、納品ボタン)と、見える掲示板(受注ボタン、期限)。解放依頼は別枠で「達成で開くもの」を表示

- 派遣タブ: 行き先にワールドの全ノード(ダンジョンと、護衛・運搬の目的地)。「往復N日+現地M日=帰還X日目」の表示。呼び戻しボタン(派遣中一覧)
- 拠点タブ: 評判と段階、勘違いの噂(Scene)の表示

## タスクR: playstyles.ts(第3波、Qと並列)

**所有ファイル**: `scripts/playstyles.ts`、`scripts/sim.ts`

- 3通りの bot を60日: `no-quests`(依頼を受けない、森と坑道を回す)/ `quests-lazy`(受けるが締め切りを見ない)/ `quests-deadline`(締め切りの近い順に優先)。指標: 60日目の所持金、評判、達成数、失敗数、隊員数、平均Lv、借金日数
- 「締め切りだけで圧力が十分か」= quests-deadline が quests-lazy より所持金・評判で明確に上回り、no-quests が赤字で詰むこと。満たさなければ、報酬倍率・納期倍率をどう動かすかを再実行で2〜3案

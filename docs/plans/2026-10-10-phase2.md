## 決定事項(本体の設計判断。変えない)

| 項目 | 決定 |
|---|---|
| 行動種別 | `explore` 探索 / `gather` 採集 / `hunt` 討伐 / `boss` ボス / `survey` 踏査。`escort` / `transport` はフェーズ4 |
| 採集 | 対象素材を指定。**既知の**採取点のうち対象素材のものを巡る(その派遣で未消化のもの)。全部回ったら入口へ戻って終了(早帰り)。未踏には踏み込まない |
| 討伐 | **既知の**巣(nest)とシンボルを巡る。対象モンスターの指定は探索率100%で解放(それまでは全部の巣)。全部回ったら入口へ戻って終了。巣に寄る途中の床では通常どおり遭遇 |
| ボス | シンボル/ボスマスを**踏んだことがある**ときだけ指定可。既知の道で直行し、戦って、戻る |
| 踏査 | `confirmed: false` のダンジョン(噂だけ)に入る。中身は探索と同じで、帰還時に `confirmed = true` にする。踏査は踏査でしか入れない(未確認のダンジョンに探索は出せない) |
| 見込み表示 | 出発前に同じ条件で N=40 回、**既知のマスだけを歩く**(`knownOnly`)シミュレーションを回し、全滅率・撤退率・平均負傷日数・想定戦闘回数を出す。未踏の中身は見ない。探索率が低いほど「未踏が多く見込みは不確か」の注記を強める。隊の戦力と推奨戦力の比も4段階(余裕/適正/厳しい/危険)で出す |
| 複数隊 | core は既に4隊まで対応。UI で派遣中の隊を並べ、同じダンジョンへ複数隊が出ているとき、地図は帰還順にマージ(今の仕組みのまま) |
| 2つ目のダンジョン | `old_mine` 古い坑道。初期状態は `confirmed: false`(噂)。踏査の行き先。難度はフェーズ3の装備前提で高め |
| 数値の置き場 | `explore.ts` と `game.ts` 先頭の定数を `src/data/tuning.json` に移す。`data.ts` が `TUNING` として読み込む |

- `explore.ts` 先頭の `// ---- sim で調整する値 ----` の定数(BASE_STEPS 〜 RETURN_RELATION)と `game.ts` 先頭の定数(START_GOLD 〜 DAYS_MAX。`START_JOBS` と `BUYABLE` と上限3つは除く)を JSON に移す
- JSON の形: `{ "explore": { "baseSteps": 16, "costKnown": 1, ... }, "game": { "startGold": 500, ... } }`。キーは lowerCamel。配列はそのまま(`"trapDamage": [0.1, 0.2]`)
- `data.ts`: `import tuningJson from '../data/tuning.json'; export const TUNING = tuningJson as Tuning;`。`Tuning` 型は data.ts 内に interface で定義(explore / game の2段)
- `explore.ts` / `game.ts` では `const T = TUNING.explore;`(game は `TUNING.game`)として参照を置き換える。export していた `BASE_STEPS` / `START_GOLD` / `START_POTIONS` / `UPKEEP_PER_DAY` は、同名の export を `TUNING` 由来の値で残す(他ファイルが import しているため)
- 整合テスト: `TUNING.explore` と `TUNING.game` の全値が number か number[] であること、`baseSteps > 0`、`costUnknown >= costKnown`
- 値は1つも変えない。`npm run sim -- 20 30` の出力がタスク前と**完全に同じ**であることを確認して報告(前の出力は docs/VERIFICATION.md の「フェーズ1 完了」の表)

## タスクH: 行動種別と見込み(第2波、G・I の後)

**所有ファイル**: `src/core/explore.ts`、`src/core/readiness.ts`(新規)、`src/core/game.ts`、`tests/explore.test.ts`、`tests/readiness.test.ts`(新規)、`tests/game.test.ts`

### explore.ts

`ExploreInput` に足す:

```ts
action: ActionKind;                 // 'explore' | 'gather' | 'hunt' | 'boss' | 'survey'
target?: { item?: string; enemy?: string };
/** 見込み用: 既知のマスだけを歩き、未踏には踏み込まない */
knownOnly?: boolean;
```

- 目標選びを行動種別で切り替える:
  - `explore` / `survey`: 今のまま
  - `gather`: 候補 = 既知(visited)の gather マスで `item === target.item`、その派遣で未消化のもの。フロンティアは候補にしない。候補が無くなったら `mapFull` と同じ扱いで入口へ(ログ「採り尽くした」)。採取点に着いたときの採取量は `pack` 込みで+1(採集指示の集中ボーナス)
  - `hunt`: 候補 = 既知の nest / symbol / boss マスで未消化のもの。`target.enemy` があれば `enemy === target.enemy` のものだけ。無くなったら入口へ(ログ「巣を回り終えた」)
  - `boss`: 候補 = 既知の symbol / boss マス(1つ)。着いて戦ったら入口へ。`target` 不要
  - `knownOnly: true` ならどの行動でもフロンティアを候補から外し、`hidden` の発見判定もしない
- 隊長の性格の寄り道(`detour`)は `explore` / `survey` のときだけ効かせる。採集・討伐・ボスでは指示が優先
- `ExpeditionResult.questProgress` は使わない(フェーズ4)。代わりに `result.kills` と `result.materials` で十分

### readiness.ts(見込み)

```ts
export interface Readiness {
  runs: number;
  wipeRate: number; retreatRate: number;
  avgInjuryDays: number;        // 人・派遣あたり
  avgFights: number;            // 想定戦闘回数
  powerRatio: number;           // 隊の戦力 / ダンジョンの recommended
  grade: '余裕' | '適正' | '厳しい' | '危険';   // powerRatio で 1.3 / 1.0 / 0.8 を境に
  uncertainty: '低' | '中' | '高';            // 探索率 70%以上 / 30〜70% / 30%未満
}
export function assessReadiness(s: GameState, o: DispatchOrder, runs = 40): Readiness;
```

- `rngFor(s.seed, 'forecast', s.counters.dispatches, i)` で i 回目を回す。`knownOnly: true`。隊員は `structuredClone`
- 戦力は `powerOf` の合計(4人未満ならそのまま)
- 想定戦闘回数は `result.kills` の合計ではなく、`runExploration` の `trace.events` で `nest` / `symbol` / `encounter` を数える

### game.ts

- `dispatch` の検証を足す: `survey` は `confirmed: false` のダンジョンにだけ、`explore` / `gather` / `hunt` / `boss` は `confirmed: true` にだけ。`boss` は symbol/boss マスを踏んだことがあるときだけ。`gather` の `target.item` はそのダンジョンの採取点に存在する素材だけ。`hunt` の `target.enemy` は探索率100%のときだけ指定可
- `newGame`: `old_mine` の進捗を `{ confirmed: false, floors: { f1: { visited: [], hiddenFound: [] } }, bossDefeated: 0, fullCleared: false }` で入れる
- `applyReturn`: `survey` で帰還したら `confirmed = true`、お知らせ「古い坑道の入口を確認した」。symbol/boss を倒したら `bossDefeated++`。探索率が100%になったら `fullCleared = true` とお知らせ
- `assessReadiness` を game.ts からは呼ばない(UI が呼ぶ)

### テスト

- 採集: 対象素材の採取点だけを回り、未踏には入らず、回り終えたら早く帰る(days より短い日数で帰る)
- 討伐: 既知の巣を回り、未踏には入らない
- ボス: シンボルを踏んだ知識があれば直行して戦う。無ければ dispatch が ok:false
- 踏査: confirmed=false にだけ出せ、帰還で confirmed=true
- knownOnly: 新しく踏むマスが 0
- readiness: 同条件で同じ値(決定論)、knownOnly なので探索率0のときは戦闘回数0かつ uncertainty '高'、戦力比で grade が変わる

## タスクJ: UI と sim の更新(第3波、H の後)

**所有ファイル**: `src/ui/**`、`scripts/sim.ts`

- 派遣タブ: 行き先(確認済みダンジョン+噂のダンジョンは踏査のみ)、行動種別(選べないものは理由付きで無効)、対象(採集=素材、討伐=100%ならモンスター)、隊長を選ぶと **性格の `exploreDesc` を表示**、「見込み」ボタンで `assessReadiness` の結果(4段階・全滅/撤退率・負傷・戦闘回数・不確かさ)を表示
- 地図タブ: ダンジョンの切り替え(確認済みのみ)。帰還した遠征の隊長名と性格を強調の説明に出す
- ログタブ: 行動種別と対象を見出しに
- sim.ts: 行動種別を引数で選べるように(`--action gather --item herb` 程度)。既定は explore で出力は変えない
- 幅375pxで崩れないこと。ブラウザで 踏査→古い坑道の探索→採集→討伐→ボス の流れを通して報告

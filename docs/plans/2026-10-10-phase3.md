## 決定事項(本体の設計判断。変えない)

| 項目 | 決定 |
|---|---|
| 属性 | `fire` 火 / `ice` 氷 / `thunder` 雷 / `earth` 土 / `dark` 闇 の5種。敵の攻撃に属性が付くことがあり、防具・装飾の `resist` で被ダメージを `×(1 − resist)` に減らす(上限0.8)。武器の属性はフェーズ6 |
| 装備枠 | 武器1・防具1・装飾1(`Equipment`)。防具は `armorClass` が職の `armor` に含まれるときだけ。装備は在庫のスタック(個体差なし)。付け替えは待機中のみ |
| 装備の効き方 | `effectiveStats` で職の倍率・適性係数の**後**に `mods` を加算(特性の加算と同じ段)。`resist` は戦闘で被ダメージに掛かる。`effects` はフェーズ3では `gather`(採取量+N)と `carry`(積載+N)の2種だけ |
| 拠点マップ | 5×5。施設は1マス。隣接は上下左右。配置はプレイヤーが空きマスを選ぶ。移動費用なし |
| 施設(フェーズ3は5つ) | 宿舎 `dorm` / 工房 `workshop` / 調合所 `alchemy` / 治療所 `clinic` / 訓練所 `training`。Lvは最大2。費用は 資金+素材+日数。維持費は施設ごとに日額(小さく) |
| 施設の効果 | 宿舎: 雇用上限+2/Lv(フェーズ4で使う)/ 工房: 装備レシピが作れる、Lv2で日数−1 / 調合所: 消耗品レシピ、Lv2で産出+1 / 治療所: 負傷日数−1/Lv、治療の疲労回復+5/Lv / 訓練所: 経験値+20%/Lv |
| 隣接シナジー(3組) | 工房×調合所「職人通り」: 両方の完成日数−1 / 治療所×宿舎「静かな寮」: 待機中の疲労回復+10/日 / 訓練所×宿舎「朝練」: 待機中に経験値+2/日。**ゲーム内に一覧表示する(隠さない)** |
| 施設勤務 | 待機中の冒険者を工房・調合所に1人ずつ置ける(`assignment: { facility }`、`status: 'working'`)。勤務中は派遣に出せない。工房は器用さ、調合所は採取の実効値が 12 以上なら完成日数−1(Lv2の−1と重なる。最低1日) |
| クラフト | レシピ = 施設+素材+資金+日数 → 完成品を在庫へ。同じ施設で同時に1件。完成は `advanceDay` で `doneDay <= day` のとき。工房・調合所がないと作れない |
| 建材 | フェーズ3は素材(苔鉄鉱・鉄鉱石)と資金で建てる。製材所・石切場はフェーズ6 |
| 古い坑道の難度 | 装備無しの固定4人(Lv3前後)で全滅率 30%以上、森の装備一式(革の鎧+骨の短剣+回復薬)で 10%未満 を目標に敵の値を sim で決める |
| テストプレイ用の経済 | フェーズ1で赤字が分かっている。フェーズ3では「初期支援金 1〜5日目に 60G/日」を入れる(前作の仕組み)。依頼が入るフェーズ4で見直す |

## 敵の属性(enemies.json に足す)

| 敵 | element(攻撃属性) | resist |

| ゴブリン / 森狼 / ゴブリンの頭 / 洞窟コウモリ | なし | なし |

## タスクK1: 装備と属性(第1波)

**所有ファイル**: `src/core/adventurer.ts`、`src/core/combat.ts`、`src/core/explore.ts`(効果 gather/carry の反映だけ)、`src/core/equipment.ts`(新規)、`src/data/items.json`、`src/data/enemies.json`、`tests/adventurer.test.ts`、`tests/combat.test.ts`、`tests/equipment.test.ts`(新規)

- `items.json` に装備6種と `hi_potion` を追加(表どおり。`kind` は weapon/armor/accessory/consumable、`equip` は types.ts の形)
- `enemies.json` に `element` / `resist` を追加(表どおり)
- `adventurer.ts`: `effectiveStats` が `a.equipment` の3枠の `mods` を加算する。`equipResist(a): Record<ElementId, number>`(合計、上限0.8)。`equipEffect(a, key)`(gather / carry の合計)。`carryCapacity` に `carry` 効果を足す
- `combat.ts`: `Unit` に `resist: Record<ElementId, number>` を持たせ(`makeAllyUnit` が `equipResist` から、敵は `def.resist`)、敵の通常攻撃と範囲スキルに `def.element` があれば被弾側の resist で `×(1 − resist)`。属性の無い攻撃は影響なし
- `explore.ts`: 採取量に隊の `equipEffect(gather)` の合計を足す。積載は `carryCapacity` 経由で自動
- `equipment.ts`:
  ```ts
  export function canEquip(a: Adventurer, itemId: string): { ok: true } | { ok: false; reason: string };  // 待機中、kind、armorClass、在庫
  export function equip(s: GameState, advId: string, itemId: string): Result;   // 在庫−1、外した物は在庫+1
  export function unequip(s: GameState, advId: string, slot: EquipSlot): Result;
  ```
- テスト: 装備で atk/def が増える、重装は僧侶に着けられない、派遣中は付け替え不可、在庫が減り外すと戻る、resist で被ダメが減る(dark 0.5 で骸骨兵の与ダメ半減、固定seedで決定論)、resist 合計の上限0.8、gather 効果で採取量+1、セーブの `equipment` が無い旧データでも落ちない(migrate は本体)

## タスクK2: 拠点・施設・クラフト(第1波、K1と並列)

**所有ファイル**: `src/core/game.ts`、`src/core/base.ts`(新規)、`src/core/craft.ts`(新規)、`src/data/facilities.json`、`src/data/synergies.json`、`src/data/recipes.json`、`tests/game.test.ts`、`tests/base.test.ts`(新規)、`tests/craft.test.ts`(新規)

- JSON 3つを表どおりに。`FacilityDef.costs[lv-1] = { gold, materials, days }`、`upkeep`、`effectText[lv-1]`、`workSlots` / `workStat`。`SynergyDef { id, a, b, name, desc, effect }`。`RecipeDef` は types.ts の形(`unlockedBy` は未使用)
- `base.ts`:
  ```ts
  export function canBuild(s, facilityId, x, y): Result;          // 空きマス、資金、素材、同じ施設は1つ
  export function build(s, facilityId, x, y): Result;             // 資金・素材を引き、construction を立てる(days 後に Lv1)
  export function upgrade(s, facilityId): Result;                 // Lv2 へ(建設中は不可)
  export function facilityLevel(s, facilityId): number;           // 建設中は前のLv(新築なら0)
  export function activeSynergies(s): SynergyDef[];               // 隣接している完成済みの組
  export function synergyValue(s, key): number;                   // effect[key] の合計
  export function listSynergies(): SynergyDef[];                  // 全組(UIの一覧用、隠さない)
  export function assignWorker(s, advId, facilityId): Result;     // 待機中のみ、枠1
  export function unassignWorker(s, advId): Result;
  ```
- `craft.ts`:
  ```ts
  export function availableRecipes(s): RecipeDef[];               // 施設が完成しているもの
  export function canCraft(s, recipeId): Result;                  // 素材・資金・施設が空いている
  export function startCraft(s, recipeId): Result;                // 素材・資金を引き、CraftJob を積む。日数 = recipe.days − (施設Lv2 ? 1 : 0) − (勤務者の該当能力 ≥ 12 ? 1 : 0) − (シナジー craft_street ? 1 : 0)、最低1
  export function craftDays(s, recipeId): number;                 // 上の日数(UI 表示用)
  ```
- `game.ts` の `advanceDay` に足す(順序は 日給→**維持費(施設の upkeep 合計を加算)**→赤字→day++→帰還→**建設の完成**→**クラフトの完成(在庫へ、お知らせ)**→待機者の回復(治療所・シナジーの補正)→**訓練所の経験値補正は applyReturn の expGain に ×(1+0.2×Lv)**→忠誠)。初期支援金: 1〜5日目に 60G(台帳「初期支援金」)。`newGame` は施設なし
- 治療所: `applyReturn` で負傷日数 −Lv(最低1)。待機者の回復で疲労 −25 −5×Lv −(quiet_dorm ? 10 : 0)
- 勤務中(`status: 'working'`)の者は派遣できず、回復はする
- テスト: 空きマスにだけ建つ、資金・素材不足で断る、完成日に Lv1 になる、隣接でだけシナジーが立つ(斜めは不可)、クラフトの日数式、完成日に在庫に入る、勤務者は派遣不可、治療所で負傷が短い、訓練所で経験値が増える、初期支援金が台帳に載る、同seedで決定論

## タスクL: UI(第2波、K1・K2の後)

**所有ファイル**: `src/ui/**`

- 拠点タブ: 5×5 の区画図(CSS grid)。空きマスを選んで施設を建てる(費用・日数・効果を表示)。建設中は残り日数。施設を選ぶと Lv上げ、勤務者の割り当て(待機中から選ぶ)。**シナジー一覧**(全3組と、今成立している組)。工房・調合所を選ぶとレシピ一覧(素材の有無、日数、資金)と「作る」、進行中のジョブと完成日
- 名簿: 各人に装備3枠。選ぶと在庫から付け替え(着けられない物は理由付きで無効)。実効能力の変化を表示
- 在庫: 装備も表示(売却可)
- 派遣タブ: 隊員の装備の有無を1文字で(武/防/飾)
- 幅375pxで崩れないこと。ブラウザで 建設→完成→クラフト→装備→古い坑道へ の流れを通す

## タスクM: sim の更新(第2波、Lと並列)

**所有ファイル**: `scripts/sim.ts`、`scripts/playstyles.ts`

- `--plan forest-then-mine` と `--plan mine-naked` の2通りを足す:
  - `mine-naked`: 1日目から古い坑道を踏査→探索(装備なし)。全滅率・負傷・探索率を出す
  - `forest-then-mine`: 森を探索しつつ素材を貯め、工房(と調合所)を建て、革の鎧×4・骨の短剣×2・回復薬を作って全員に着けてから(目安15日目)、古い坑道へ。同じ指標を出す
- 2通りの比較表(全滅率、平均負傷日数、30日目の坑道の探索率、所持金)を出す → 「鎖が機能するか」の答え。目標は mine-naked 全滅率 30%以上、forest-then-mine 10%未満
- 目標から外れていたら、敵の値(skeleton / cave_bat / golem の hp・atk)をどう動かすと近づくかを、値を変えた再実行で2〜3案出す(JSON は変えず報告だけ)

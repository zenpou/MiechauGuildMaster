# 自動探索を「見守れる」画面にする設計案

2026-10-20 / 第1〜9節は参考映像の調査・設計時点の記録。ユーザーの承認後にサンプルと本体実装へ進み、第10節以降に実装・検証状況を追記した。

## 提案の中心

「次の日へ」の間に、隊が実際に選んだ道を進み、採集・遭遇・戦闘・休憩・引き返しを行う様子を見る。

取り入れたいのは、**隊の自律的な判断が、位置・地図・体力・出来事の変化として分かること**。移動アニメーションだけを足すのではなく、「この隊長だから寄り道した」「消耗したので休んだ」「今回は奥まで届かなかった」が次の編成・装備・方針の判断につながる画面を目指す。

## 2. このプロジェクトでは何が既にあるか

現行コードを確認した内容。

| 既存機能 | 現状と活用先 |
|---|---|
| 1マス単位の移動 | `src/core/explore.ts` の `move()` が経路と歩数を記録している |
| 自律判断 | 未踏探索、性格による寄り道・迷い・休憩、撤退、入口への帰路がある |
| 戦闘 | `src/core/combat.ts` の共通処理。探索側から呼び出され、行動ログが作られる |
| 行程の確定 | `dispatch()` が出発時に全行程を決める。日送りでは結果を再抽選しない |
| 移動の調査用記録 | `ExploreTrace` に日ごとの `moves` とイベントがあるが、派遣の保存データには残らない |
| 保存済みの記録 | `Expedition.steps` はワールド上の位置、`result.log` は日付付きの文章、`mapDeltas` は帰還後に反映する地図差分 |
| 地図画面 | 帰還後の既知マスと前回の踏破箇所を表示。隊の移動は再生しない |
| 日送り | `src/ui/home.ts` の `nextDay()` で1日進め、報告と物語を表示する |

土台となる自動探索はある。主な不足は、**順序・位置・状態の変化を保存し、見せる部分**。

なお `ExploreTrace.moves` と `events` は別配列で、移動と出来事の共通の連番がない。同じマスへの再訪もあるため、現状の配列だけから後付けで正確な時系列を復元する方針は取らない。

## 3. 時間の進め方

### 推奨案：日送りに「その日の冒険を見る」段階を入れる

```text
朝の経営・準備・派遣
    ↓ 次の日へ
進めた1日分の冒険を観察
    ├ 移動 → 採集・宝箱
    ├ 移動 → 遭遇 → 自動戦闘 → 探索再開
    └ 消耗 → 休憩 / 引き返し / 野営
    ↓ 見終える、または結果へ
翌朝の帰還報告・メール・物語・経営
```

ゲーム内時間は現行の日単位のまま。画面内では、1日の出来事を順番に見せる。速度やスキップで結果は変わらない。

| 方式 | 長所 | 負担・注意点 |
|---|---|---|
| **日送り時に観察（推奨）** | 初回の派遣から、出した隊が実際に冒険している感覚を得られる。現在の経営サイクルにも合う | 毎日の義務的な待ち時間にしないため、結果へ進む操作と観察の省略が必要 |
| 後から「道中を見る」を開く | 経営を中断せず、気になる隊だけ確認できる | 自分で開かなければ、現在の「日を進めて結果を待つ」体験のまま |
| 経営画面と並行して常時進行 | 遠くで活動している印象が強い | 日付・報酬・呼び戻し・放置時間の扱いが変わる。現行の日送り設計の変更が必要 |

推奨は、日送り時の観察と、後から道中を見直す機能の組み合わせ。常時進行への変更は別の判断とする。

## 4. 画面と動き

### 4.1 基本配置

- **上部**：観察している日、隊の切り替え、行き先、現在の行動。
- **中央左**：探索地図と隊の印。既知の道・今回歩いた道・未踏を区別する。
- **中央右**：隊員の顔と名前、HP、直近の出来事。
- **下部**：一時停止、速度変更、次の出来事、結果へ。
- スマホでは地図 → 隊の状態 → 出来事 → 操作の順で縦に並べる。細かな情報のために地図を小さくしすぎない。

最初は隊全体を1つの印で表す。参考映像のように経路と行動が読めればよく、4人全員の歩行スプライトは初版の前提にしない。隊員それぞれの存在感は、顔・HP・発言・戦闘時の行動で出す。

### 4.2 状態ごとの表示

| 状態 | 動き | 表示する内容 |
|---|---|---|
| 移動 | 隣接するマスへ印を移す。壁や未到達のセルを横切らない | 隊長・探索方針・現在位置 |
| 未踏に侵入 | 到達した位置から見える範囲を開く。探索率は踏んだマスだけ増やす | 新規踏破数、今回の進捗 |
| 分かれ道で迷う | その場で短く止まる | 実際に迷った記録があるときだけ、その旨を出す |
| 採集・宝箱 | 対象位置で止まり、取得内容を短く表示 | 拾得量と荷物。まだ持ち帰っていない成果として扱う |
| 遭遇 | 移動を止め、「戦闘中」に切り替える | 敵の名前・数、味方の状態 |
| 戦闘 | 攻撃した人物、被害、回復を順に強調。HPを対応する時点で更新 | 既存の戦闘処理が出した行動・数値 |
| 戦闘終了 | 勝利・逃走・全滅を表示。続行可能なら地図へ戻る | 戦利品、消耗、次の行動 |
| 休憩 | 隊の印を止め、休憩表示とHPの回復 | 既存の休憩判断の結果 |
| 引き返し | 確定した帰路を歩く | 撤退の理由、帰路にあること |
| 野営 | その日の終点で停止 | 翌日も現地にいること |
| 日の終わり | 観察を区切る | 帰還した隊は報告へ、継続中の隊は翌日へ |

地図の記号や色には凡例を付け、重要な状態は文字でも表示する。画面の揺れ・点滅は必須にしない。

### 4.3 表示テンポの初期案（未計測）

- 通常移動：1マス0.2〜0.35秒程度。
- 採集・発見：0.6〜1秒程度。
- 戦闘：詳細表示では行動単位、早送りでは戦闘のまとまり単位で進める。
- 速度はまず1倍・4倍・8倍。「次の出来事」で移動区間を飛ばす。
- 長い遠征を全日分まとめて強制再生せず、日送り1回につき1日分。
- 初回は見守る楽しさを優先。その後は省略でき、ログから見直せる。
- 動きを減らす設定では補間移動・点滅を省き、同じ順序の状態変化を段階表示する。

これらは参考作の数値ではなく、このプロジェクト用の出発点。実際の歩数・戦闘数で所要時間を測り、待たされるなら短縮する。

## 5. プレイヤーが判断できるようにする

「何が起きたか」に加えて、次の派遣を考える手がかりを残す。

- 探索を急いだ隊は奥へ進むが、埋め残しが見える。
- 宝箱に寄った隊は、主経路から外れて戻る様子が見える。
- 回復役がいる隊は、回復が誰によるものか分かる。
- 疲れや負傷で引き返した隊は、HPと撤退理由が対応する。
- 同じ場所への再派遣では、既知の道を通って先へ向かう違いが見える。

ただし、理由の文は実際の判断記録に基づく。経路だけを見て「性格のせい」「危険を察した」などの理由を後から創作しない。

## 6. 現行仕様との境界

### 観察と確定処理

- 探索・戦闘・報酬の計算は、現在の共通ロジックで1回だけ行う。
- 再生速度、一時停止、表示対象の隊、スキップは表示だけを変える。
- 現行の `advanceDay()` は帰還・成長・通知までまとめて処理する。初版はこの一度の処理と保存を維持し、その後に観察画面を出す。
- 観察画面の下の経営画面は操作できないようにし、帰還報告・物語・エンディングは観察を閉じてから見せる。
- 再生中に読み込み直しても、日送り・報酬をもう一度実行しない。確定済みの翌朝に復帰し、保存された行程を見直せるようにする。

### 未来の情報

- 観察対象は、日送りで終わった日まで。明日以降の経路・戦闘・成果を出さない。
- 地図は出発時の知識から再生地点までの記録で作る。帰還後に更新された地図をそのまま敷くと、まだ歩いていない経路が先に見えてしまう。
- 途中の隊について、未確定の帰還報告の成功/全滅バッジや最終戦利品を先に出さない。
- 観察中に見えた新しい地形は「今回の観察」で示し、正式な地図台帳・在庫・経験値への反映は現行の帰還処理に合わせる。
- 別の隊が同じ日に同じ地図を調べた場合も、後から判明した情報を過去の再生に混ぜない。

### 呼び戻し

参考作の酉では探索中の「帰還」が見える。一方、本作は日単位で結果が確定するため、その操作をそのまま置くと「表示中の戦闘へ介入できる」と誤解される。

初版案は、**観察中は一時停止して状況を読み、翌朝の経営画面で呼び戻す**。既存の「現地の成果は持ち帰れない」仕様は明記する。開示済みの移動・出来事は残し、呼び戻し後の未公開行程は破棄する。

同日の途中で命令を送り、以後の経路・報酬を変えたい場合は、途中状態から継続するシミュレーションと収益計算の再設計が必要。それは今回の表示機能とは別の仕様変更。

### 日帰りと既存の依頼書

`docs/plans/2026-10-20-codex-request-daytrip-and-journey.md` にある「日帰りを既定にする」「昨日までの文章ログを見せる」は未実装。今回の希望は、その依頼書で別件とされていた地図上の移動表示に相当する。

日帰りなら「出発 → 次の日へ → その日の探索を見る → 翌朝の帰還報告」が1回でつながるので相性はよい。ただし既定日数変更と経済バランスは、この設計メモでは確定・実装しない。

## 7. 実装する場合のデータ方針

保存用の行程記録を、計測用 `ExploreTrace` とは別の型で持つ。

- 対象ダンジョン・階・隊員。
- 出発時点の既知マス・隠し通路。
- 遠征内の相対日と単調増加する順序番号。
- `移動 / 発見 / 採集 / 遭遇 / 戦闘行動 / 休憩 / 引き返し / 野営 / 終了` の順序付き記録。
- 各記録の位置。戦闘・回復・罠などでは、その時点のHPまたはHP差分。
- 取得物と行動者は既存の処理が確定した値を記録する。

移動フレームに全員のHPや地図全体を毎回複製しない。出発時の状態と変化分を残す。履歴の最大保持数で容量を測る。

文章ログを解析してダメージ・行動者・地図位置を推測する方法は採用しない。戦闘の詳細表示に必要な情報は `runCombat()` の出来事の出力として追加し、ゲームの計算は共通のままにする。

往路の日数がある遠征では、現地探索の日を遠征全体の日付へ変換する。往路で倒れて現地に着いていない場合は現地の再生を作らない。往復の表示はワールドの道を使い、ダンジョン内の歩行データと混同しない。

古いセーブには行程記録がないので、既存ログを表示する。現在の装備や地図から過去の探索を再計算しない。

## 8. 実装の区切りと確認条件

### 最初に作る範囲

1. 森の洞窟・1隊について、入口→実際の経路→イベント→帰路が見える。
2. 地図の開示、隊の印、行動ログ、味方HPが同じ順序で動く。
3. 一時停止・倍速・次の出来事・結果へ、帰還後の見直しを用意する。
4. 派遣中の翌日分、複数日、往復、呼び戻し、旧セーブへ広げる。
5. 複数隊はまず切り替えて観察。異なる隊の歩数番号を実時間として同期させない。

初版では、歩行スプライトの全員分制作、常時リアルタイム化、同日の戦闘への指示、参考作の天候・SP・隊列制度の新規導入は含めない。

### 実装時の受け入れ条件

- 同じseed・出発条件で、観察あり/なし・倍速・スキップの結果が完全に一致する。
- 移動が隣接マスをたどり、イベントが実際の位置と順序で起きる。
- 探索率は見えただけのマスで増えず、隠し通路を発見前に漏らさない。
- 日付境界、早帰り、全滅、野営、呼び戻しで未来の記録を表示しない。
- 報酬・成長・帰還・章の開始を重複実行しない。
- 開示済みの記録は呼び戻しても失わず、未公開の旧行程を再生しない。
- 読み込み直し・旧セーブ・履歴の見直しが安全に動く。
- 375px幅で地図と操作が収まり、キーボードと「動きを減らす」設定でも内容を読める。
- 複数隊・長い遠征で再生時間と保存容量を計測する。

## 9. 今回の成果と未決事項

確認したもの：酉の初回探索の映像・説明、現在の本作の探索処理、日送りと保存の境界。

成果：この設計案と、動きの関係を試す説明用の見本。見本の数値・戦闘・経路上の出来事は架空であり、実ゲームのシミュレーション結果や参考作品の再現ではない。

未決：日送り時の観察を標準にするか、任意で開く方式にするか。戦闘を行動単位で見せる範囲。表示速度の実測値。呼び戻しを日単位より細かくするか。

## 11. 本体への組み込み

- 日送りで `advanceDay` と保存を先に済ませ、昨日の探索を観察する。観察UIは結果を再計算せず、閉じる際にも報酬を適用しない。

- 派遣中は「道中を見る」、帰還履歴は「道中を再生」。見られる日は現在の前日まで。自動観察では最終的な勝敗を冒頭に出さない。

- 観察記録がない旧セーブの遠征は、従来の文章ログを使用する。過去の探索の再計算はしない。

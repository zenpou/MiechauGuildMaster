# フェーズ5 実装プラン: 冒険者の個性とメール

> 2026-10-10。ROADMAP フェーズ5。設計の正本は [DESIGN.md](../DESIGN.md) 第6節(忠誠の式・メール10種の表・個性・ユニーク・スキル訓練)。
> 規約と共有IDは phase1〜4 のプランを引き継ぐ。台詞・キャラ名は**すべて仮**(「(仮)」付き)で、フェーズ7で書き直す。
> 「確認したいこと」: メールで「数字に見えないもの」が伝わるか。

## 決定事項

| 項目 | 決定 |
|---|---|
| 受信箱 | `GameState.mails`(types.ts の `Mail`)。未読数をタブに出す。返信は `choices` から1つ選ぶと `answered` に入り、効果を即時適用。返信しないまま7日で「保留」扱い(昇給は再送) |
| 発火 | 第6節の表どおり。判定は `advanceDay` の忠誠+1の後に `mail.ts` の `checkMails(s, rng, notices)` で行う。1日に同じ人からは1通まで、全体で3通まで(多すぎると読まない) |
| 昇給 | `desiredSalary(a) = salaryOf(a)`(Lv込みの再計算)。`a.salary < desired × 0.85` で要望。承認で `a.salary = desired`、忠誠+5。保留は7日後に再送(2回まで)。断ると忠誠−20、`history.raisesRefused++` |
| 退職 | 拒否2回連続 または 忠誠30未満 で警告メール(`history.warnedDay = day`)。警告から7日以内に昇給承認で撤回。7日過ぎたら自己退職(メール、名簿から消え `flags['gone:' + id] = true`。候補者に二度と出ない)。忠誠10未満でも即警告→7日 |
| 休みたい | 疲労70超のまま派遣に組まれた翌日(`dispatch` 時に `flags['tiredDispatch:' + id] = day`) |
| 仲間への不満 | 関係値−40以下の相手と連続3回同じ隊(`history` に `lastPartyMates: string[]`… は型変更になるので `flags['mates:' + id] = JSON文字列` で3回分を持つ) |
| 噂メール | 酒場はフェーズ6なので、探索率50%/100%到達時のみ。内容は「次のダンジョンの噂」(未確認のダンジョン名)を1行 |
| 文面 | `src/data/mail-text.json`: kind × 性格(6)の定型。`{name}` `{salary}` `{desired}` `{mate}` `{dungeon}` を差し込む。口調は性格別(慎重=丁寧、勇敢=短く威勢、強欲=金の話、仲間思い=気遣い、自信家=自慢、臆病=弱気)。全部「(仮)」付き |
| 帰還のひとこと | `src/data/return-lines.json`: 性格(6)× 結果(成功/撤退/全滅/早帰り)× 2〜3通り。`ExpeditionResult.returnDialogue` に隊員全員分。ログの末尾とお知らせに出す |
| スキル訓練 | 訓練所で `trainSkill(s, advId, skillId)`: 日数3・費用150(`tuning.training`)。`assignment: { training, untilDay }`、`status: 'training'`。完了で `a.skills` に追加。訓練スキルは `src/data/skills.json` に `kind: 'trained'` として5つ: `tough` 体力増強(hp+10)/ `might` 剛力(atk+2)/ `ironskin` 鉄壁(def+2)/ `fleet` 俊足(spd+2)/ `keen_eye` 目利き(gather+2 scout+1)。パッシブで `effectiveStats` に加算。1人2つまで |
| 組み合わせイベント | 1件: 関係値60以上の2人を同じ隊で累計5回出すと「親友」(両者 忠誠+10、関係値+20、メール)。`flags['pair:' + a + '|' + b]` に回数。取り返しのつかない要素はフェーズ6以降 |
| ユニーク冒険者 | 1人、仮名「ユニークA(仮)」。加入条件: 10日目以降に評判8以上で候補者として現れる(`unique: 'u_alpha'`、契約金なし)。固有スキル `u_alpha_skill`(パッシブ、scout+3)。依頼チェーン1本(3段): 1. 森で薬草5納品 → 2. 坑道へ3回派遣 → 3. 単独(1人)でゴブリンの頭を討伐 → 報酬: `moss_charm` レシピの代替として「上級への転職券」はフェーズ6なので、ここでは忠誠+30・固有依頼のメール。定義は `src/data/uniques.json` |
| 候補者の表示 | 候補者の `persona`(趣味・特技・好き嫌い)を募集タブに出す(数字に見えないものの入口) |

## タスクS1: メール・忠誠・昇給・退職(第1波)

**所有ファイル**: `src/core/mail.ts`(新規)、`src/core/game.ts`(advanceDay への組み込み、dispatch の疲労フラグ、`replyMail`、退職の反映)、`src/data/mail-text.json`、`src/data/tuning.json`(`mail` 節)、`src/core/data.ts`(追加分)、`tests/mail.test.ts`、`tests/game.test.ts`

- `mail.ts`: `checkMails(s, rng, notices)`(表の発火条件をすべて)、`replyMail(s, mailId, choiceId): Result`、`unreadCount(s)`、`markRead(s, id)`、`composeMail(kind, a, vars)`(文面の差し込み)、`desiredSalary(a)`
- 挨拶は `hire` の翌日(`history.hiredDay + 1`)。忠誠の節目は `LOYALTY_MILESTONES` 到達時に一度(`flags`)
- 退職: `advanceDay` で `warnedDay + 7 < day` なら名簿から外し、派遣中なら帰還後に。候補者生成で `flags['gone:...']` を見る(名前だけなので、同名は許容)
- テスト: 各メールの発火条件、昇給の承認/保留/拒否の効果、警告→退職の流れと撤回、1日3通まで、返信で忠誠が動く、決定論、既存の sim 出力は変わらない(メールは乱数を別タグ `('mail', day)` で)

## タスクS2: 帰還のひとこと・訓練・組み合わせ・ユニーク(第1波、S1と並列)

**所有ファイル**: `src/core/training.ts`(新規)、`src/core/events.ts`(新規)、`src/core/explore.ts`(returnDialogue の生成)、`src/core/adventurer.ts`(訓練スキルの加算)、`src/data/return-lines.json`、`src/data/skills.json`(trained の追加)、`src/data/uniques.json`、`src/core/recruit.ts`(ユニークの出現)、`tests/training.test.ts`、`tests/events.test.ts`、`tests/explore.test.ts`、`tests/recruit.test.ts`

- `events.ts`: `onReturn(s, e, notices)`(組み合わせの回数とイベント、ユニークの依頼チェーン進行)。game.ts からの呼び出しは本体が S1 の後に1行足す
- ユニークの依頼チェーンは `s.flags['u_alpha:step']` で段を持ち、各段の判定は `onReturn` と `deliver`(納品は mail/quests ではなく `flags['u_alpha:herb']` を在庫から直接引く `advanceUniqueChain(s)`)
- テスト: 訓練の日数・費用・上限2・完了でスキルが付き能力が上がる、帰還のひとことが結果ごとに出る、親友イベントが5回目で起きる、ユニークが条件で現れる、チェーンが3段進む

## タスクT: UI(第2波)

**所有ファイル**: `src/ui/**`

- 受信箱タブ(新設、未読数バッジ): 一覧(未読強調)、本文、返信ボタン(choices)、返信済み表示
- 名簿: 訓練ボタン(訓練所があるとき。スキル選択と費用・日数)、所持スキル、趣味・特技・好き嫌い、ユニークの印
- 募集: persona を表示
- ログ: 帰還のひとことを末尾に。拠点: 帰還時のお知らせに一言を添える
- タブが9つになるので3段か、拠点タブに受信箱を統合してもよい(推奨: 「拠点」タブの先頭に受信箱の未読を出し、タブは「受信箱」を新設して9つを3列×3段)

## タスクU: sim(第2波、Tと並列)

**所有ファイル**: `scripts/sim.ts`、`scripts/playstyles.ts`

- playstyles に「メールに返信する(昇給は全部承認)」「返信しない」の2通りを足し、60日の 退職者数・平均忠誠・所持金 を比べる。確認したいこと「数字に見えないものが伝わるか」は人のテストプレイで見るものなので、sim は退職と忠誠の推移が壊れていないことの確認

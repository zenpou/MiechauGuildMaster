# テストプレイの手引き

bot(`npm run sim`)で測れる数字は測った。ここから先は**人が遊ばないと分からないこと**を確かめる。
気づいたことは、下の形で `docs/VERIFICATION.md` に残す(CLAUDE.md「実装方針」)。数値は体感だけで変えず、sim で裏を取ってから変える。

## 始める

```sh
npm run dev                  # http://localhost:5173
npm run dev -- --host        # スマホから見るとき。同じ Wi-Fi の http://<PCのアドレス>:5173
```

- 新しく始める: ブラウザの開発者ツールのコンソールで `localStorage.removeItem('miechau-guild-master.save.v1'); location.reload()`
- 途中から始める(bot が遊んだ状態を読み込む):

  ```sh
  npm run sim:dragon -- --seed 1 60 --dump artifacts/fixtures/day60.json     # 60日目の状態を書き出す
  ```

  ```js
  // 開発サーバーを開いたページのコンソールで
  localStorage.setItem('miechau-guild-master.save.v1', await (await fetch('/artifacts/fixtures/day60.json')).text()); location.reload()
  ```

  日数を変えれば別の進み具合になる(20〜130日)。`--seed` を変えれば別の展開。**通常の遊び用のセーブは上書きされる**ので、ブラウザのプロファイルを分けるか、先に `localStorage` の値を控えておく。

## 新規開始の案内を確認する

新規開始ではノエルの案内を進めるまで、必要なメニューだけ使える。次の順で確認する。

1. 最初は拠点・派遣だけ有効で、日送りと装備・在庫の操作は使えない。派遣には二人と安全な日帰り行程が準備されている。
2. 出発して日を進め、帰還と第一章を確認する。帰還報告→地図→依頼の順に確認ボタンを押す。確認だけでは日数・資金・素材が減らない。
3. 2回目は森1階の日帰り探索で、方針・回復薬・見込みを確認する。帰還後に募集・受信箱が開く。雇わずに次へ進める。
4. 募集の確認後に施設、施設の確認後にワールド・記録が開く。建設せずに案内を完了できる。
5. 地図の案内途中で再読み込みしても続きから再開する。「案内を終了して全機能を開く」でも終了できる。旧セーブは最初から全メニューを使える。

`node scripts/tutorial-check.cjs http://127.0.0.1:4174/ local` で、PC・375px幅の両方を上記の順に画面操作し、同seed・同じ派遣を行った案内なしの結果と比較する。先にビルドとプレビューを起動する。通常のブラウザとは独立した保存領域を使い、初期状態以外の書換えは行わない。

以下の自由な操作・従来のバランス確認では、最初に案内を終了する。計測botの保存データも案内終了済みで出力する。

## bot の進み方(比べる目安)

竜まで最短で進む bot(30 seed の中央値)。人が遅い・速い、どこで詰まるかの目安になる。

| 目標 | 日 |
|---|---|
| ① 森の洞窟を6割探索 | 5 |
| ② 古い坑道を踏査して4割探索 | 13 |
| ③ 廃れた塔f1の鍵と階段 | 31 |
| ④ 沈んだ遺跡f2の竜の紋章 | 66.5 |
| ⑤ 竜の討伐 | 113(91〜161) |

初日の名簿はティナとセラの2人、開業資金150G、募集は3日目から来る(2026-10-21)。従来のbot計測は2日目の2人で森へ出し、3日目に最初の雇用、7日目に6人。

派遣画面の既定は日帰り（現地1日）。最初は森へ1日出し、翌朝の帰還報告で成長・採取点を確認する。「この隊を組み直す」から装備・持ち物・隊長を変更して歩き方を比べる。準備ボタンで勝手に出発・製作されないこと、発見した素材を採りに行く準備へ進めることも確認する。

初回のティナ・セラの二人による森の洞窟1階の探索は入口近くの安全な日帰り行程（2026-10-21）。最初の派遣画面で二人が選択され、どちらを隊長にしても無傷で戻る。一人だけを選んだ場合も導入行程は維持する。薬なしでも無傷で戻り、薬草1個と地図の進捗が報告され、薬草が在庫に残ることを確認する。第一章は初めて帰還した後に開き、加入が重複しない。派遣せずに日を進めても第一章が先走らず、導入探索が残ることも確認する。二度目の準備では日数と方針を選べ、通常の危険・見込みに戻る。既に出発済みの探索結果は書き換わらないので、この確認は通常のセーブを残した別の確認環境で新規開始して行う。

仲間の頼みは各人物の最初の忠誠会話後に「依頼」へ出る。「受ける」だけでは材料を使わず、「渡す」で必要残数だけを納品する。次の頼みは未受注で、訪問・単独討伐は受注後の出発から数える。本編も個別会話も新規再生は1日1話まで。同日に別の条件を満たした場合、再読み込み、読み返しでもこの上限を守る。`node scripts/early-story-check.cjs http://127.0.0.1:4173/` で独立した保存領域を使い、seed 1の初回帰還→再探索→雇用→坑道踏査→個別会話→18日目の帰還と依頼操作を再現できる（先にビルドとプレビューを起動）。

## 人にしか分からないこと(見てほしい順)

1. **60〜90日で竜に届く難度か**。何日目に竜を倒したか、どこで足止めされたか(素材集め・火耐性・資金・隊員の疲労・ダンジョンの強さ)
2. **最初の数日で迷わないか**。ノエルの案内だけで、派遣 → 帰還報告 → 地図・依頼 → 再派遣 → 募集・施設・ワールドまでたどれるか。次に押す所や、メニューが開く理由が分からない瞬間があったか
3. **隠し通路に気づけるか**。塔f1の鍵まで届いたか。「探索率が100%にならない」ことに気づいて、探索を出し直したか(派遣画面の知らせは読んだか)
4. **メールで「数字に見えないもの」が伝わるか**。誰が不満か・誰が昇給を望んでいるかを、メールで知って判断できたか。返信しないと何が起きたか
5. **竜の前の備えに気づけるか**。竜の説明(ワールドの地点・ダンジョン)から「火に耐える備えが要る」と読めたか。熾火の指輪の素材(鬼火の残り火・水晶)をどこで集めると気づいたか
6. **派遣中の待ち時間が退屈でないか**。「次の日へ」を連打する日が続かなかったか。複数の隊を回す面白さがあったか
7. **画面**: スマホで読めるか、押しにくい所はないか、文字が詰まりすぎる所はないか

```
### テストプレイ YYYY-MM-DD(誰が・端末・何日分)
- 最初から / 途中(seed N の N日目)から
- 竜を倒した日: N日目(倒せなかった: N日目まで)
- 詰まった所: …(何日、何で)
- 分かりにくかった所: …
- 気になった数値: …(sim で裏を取ってから変える)
- 変えた値: …(sim の前後比較を併記)
```

# テストプレイの手引き

bot(`npm run sim`)で測れる数字は測った。ここから先は**人が遊ばないと分からないこと**を確かめる。
気づいたことは、下の形で `docs/VERIFICATION.md` に残す(CLAUDE.md「実装方針」)。数値は体感だけで変えず、sim で裏を取ってから変える。

## 始める

```sh
npm run dev                  # http://localhost:5173
npm run dev -- --host        # スマホから見るとき。同じ Wi-Fi の http://<PCのアドレス>:5173
```

- 新しく始める: ブラウザの開発者ツールのコンソールで `localStorage.removeItem('miechau-guild-master.save.v1'); location.reload()`
- 途中から始める(bot が遊んだ状態を読み込む):

  ```sh
  npm run sim:dragon -- --seed 1 60 --dump artifacts/fixtures/day60.json     # 60日目の状態を書き出す
  ```

  ```js
  // 開発サーバーを開いたページのコンソールで
  localStorage.setItem('miechau-guild-master.save.v1', await (await fetch('/artifacts/fixtures/day60.json')).text()); location.reload()
  ```

  日数を変えれば別の進み具合になる(20〜130日)。`--seed` を変えれば別の展開。**通常の遊び用のセーブは上書きされる**ので、ブラウザのプロファイルを分けるか、先に `localStorage` の値を控えておく。

## bot の進み方(比べる目安)

竜まで最短で進む bot(30 seed の中央値)。人が遅い・速い、どこで詰まるかの目安になる。

| 目標 | 日 |
|---|---|
| ① 森の洞窟を6割探索 | 4 |
| ② 古い坑道を踏査して4割探索 | 15 |
| ③ 廃れた塔f1の鍵と階段 | 35 |
| ④ 沈んだ遺跡f2の竜の紋章 | 70 |
| ⑤ 竜の討伐 | 115(84〜169) |

## 人にしか分からないこと(見てほしい順)

1. **60〜90日で竜に届く難度か**。何日目に竜を倒したか、どこで足止めされたか(素材集め・火耐性・資金・隊員の疲労・ダンジョンの強さ)
2. **最初の数日で迷わないか**。ヒント(ホームの囲み)だけで、派遣 → 帰還 → 依頼 → 施設 までたどれるか。何をしていいか分からない瞬間があったか
3. **隠し通路に気づけるか**。塔f1の鍵まで届いたか。「探索率が100%にならない」ことに気づいて、探索を出し直したか(派遣画面の知らせは読んだか)
4. **メールで「数字に見えないもの」が伝わるか**。誰が不満か・誰が昇給を望んでいるかを、メールで知って判断できたか。返信しないと何が起きたか
5. **竜の前の備えに気づけるか**。竜の説明(ワールドの地点・ダンジョン)から「火に耐える備えが要る」と読めたか。熾火の指輪の素材(鬼火の残り火・水晶)をどこで集めると気づいたか
6. **派遣中の待ち時間が退屈でないか**。「次の日へ」を連打する日が続かなかったか。複数の隊を回す面白さがあったか
7. **画面**: スマホで読めるか、押しにくい所はないか、文字が詰まりすぎる所はないか

## 記録の形(`docs/VERIFICATION.md` に追記)

```
### テストプレイ YYYY-MM-DD(誰が・端末・何日分)
- 最初から / 途中(seed N の N日目)から
- 竜を倒した日: N日目(倒せなかった: N日目まで)
- 詰まった所: …(何日、何で)
- 分かりにくかった所: …
- 気になった数値: …(sim で裏を取ってから変える)
- 変えた値: …(sim の前後比較を併記)
```
